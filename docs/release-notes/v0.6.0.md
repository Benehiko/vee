## Highlights

**vee speaks MCP — coding agents can now drive it directly.** `vee mcp` runs a
[Model Context Protocol](https://modelcontextprotocol.io) server over stdio,
so Claude Code, Cursor, Codex, and any other MCP-capable agent can manage VMs
through typed tools instead of shelling out to the CLI and parsing tab-aligned
text. The server is the ordinary `vee` binary — nothing extra to install.
Register it with your agent:

```sh
# Claude Code
claude mcp add vee -- vee mcp

# Codex CLI
codex mcp add vee -- vee mcp

# Any JSON-configured MCP client
# { "mcpServers": { "vee": { "command": "vee", "args": ["mcp"] } } }
```

A typical agent session: `vm_create {template: "devbox", start: true}` →
`vm_exec {command: "docker run --rm alpine echo ok"}` → `vm_logs` →
`vm_delete`. Every tool returns structured JSON — ports, IPs, exit codes,
health checks — so agents act on fields, not formatted terminal output.

**The MCP surface has full feature parity with the CLI.** Thirty-one tools
cover every non-interactive command: the VM lifecycle, guest command execution
via the guest agent, ports and service discovery, logs (including the guest
systemd journal), health checks, raw QMP, one-shot stats, display connection
info, backups, the base-image cache, GPU/IOMMU inspection, GitHub-runner
credentials, and the pacman mirror. Every prompt the CLI collects on a
terminal became a tool parameter, so all fifteen templates — including
passthrough, github-runner, torrent, jellyfin, and macOS guests — are
creatable over MCP. The handful of commands that stay CLI-only are the
inherently interactive or root-mutating ones (`vee ssh`'s shell, the config
TUI, GUI viewer launches, `gpu bind`, daemon install), each with a read-only
MCP counterpart where one makes sense.

Parity is enforced, not aspirational: a test walks the real command tree and
fails the build when a CLI command has neither MCP tools nor an explicitly
declared exemption — so the two surfaces cannot drift apart silently. See
[docs/mcp.md](https://github.com/Benehiko/vee/blob/main/docs/mcp.md) for the
full tool reference.

### If you already use vee

- Nothing changes unless you run `vee mcp`. The server is stdio-only — no
  network listener, no new daemon, and it runs with the privileges of the
  user who invoked it.
- `vee tunnel`, `vee ports`, and `vee create`'s github-runner path were
  refactored onto code now shared with the MCP server; behavior is unchanged.
