## Highlights

A patch release with one fix for the Linux daemon, plus dependency and
toolchain maintenance.

**The daemon can start bridge-mode VMs again.** The `vee.service` unit set
`CapabilityBoundingSet=CAP_NET_BIND_SERVICE`. A bounding set limits every
child process of the daemon too, so the setuid `qemu-bridge-helper` could not
gain `CAP_NET_ADMIN` and exited with `failed to drop privileges`. Any VM with
`--nic-mode bridge` failed to start when the daemon launched it, for example
at boot through autostart, while the same VM started fine from a shell. The
unit now keeps only `AmbientCapabilities=CAP_NET_BIND_SERVICE`, which is all
the tunnel router needs to bind port 80.

**`vee daemon install` restarts a running daemon.** It used to run
`systemctl enable --now`, which does nothing to a daemon that is already
running, so a reinstall left the old unit and the old binary in place until
the next reboot. It now enables the service and restarts it.

**Maintenance**

- Built with Go 1.27.3, with Go dependencies bumped.
- YAML handling moved from the unmaintained `gopkg.in/yaml.v3` to its
  maintained fork `go.yaml.in/yaml/v3`, which has the same API. The build no
  longer carries two copies of the library.
- `THIRD_PARTY_LICENSES` is now generated in a locale-independent order, so
  `make licenses` gives the same file on every machine.

### If you already use vee

- On Linux, run `vee daemon install` again after upgrading. The bridge fix is
  in the unit file, which is only rewritten on install, and the install now
  restarts the daemon onto the new binary for you.
